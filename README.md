# طلبيستا / Talbista

Backend (Python stdlib + SQLite) يخدم أيضًا واجهات العميل `/` والسائق `/driver` والإدارة `/admin`. لا GPS ولا تتبع مباشر.

## تشغيل محلي
    ADMIN_PASSWORD=كلمة_قوية ADMIN_PHONE=0910000000 python3 server.py     # المنفذ 8000 أو PORT
    ADMIN_PASSWORD=... DEMO_PASSWORD=... python3 seed_demo.py              # حسابات تجريبية (اختياري)
    sh run_tests.sh                                                        # كل الاختبارات

## متغيرات البيئة
- `ADMIN_PASSWORD` (إلزامي في الإنتاج)، `ADMIN_PHONE`
- `TALBISTA_DB` مسار قاعدة البيانات (في Docker: `/data/talbista.db`)
- `PORT` منفذ الخادم

## الاستضافة (Docker)
1. ابنِ الصورة من `Dockerfile` على أي منصة تدعم Docker.
2. اربط قرصًا دائمًا على `/data` وإلا ضاعت البيانات عند إعادة النشر.
3. ضع `ADMIN_PASSWORD` كسر في إعدادات المنصة، وفعّل HTTPS (توفره المنصات عادة).
4. فحص الصحة: `GET /healthz`.
5. نسخ احتياطي: انسخ ملف قاعدة البيانات دوريًا (`sqlite3 talbista.db ".backup backup.db"`).

## ملاحظات
- خادم واحد بعملية واحدة (SQLite) يناسب الإطلاق التجريبي والحجم الصغير؛ للتوسع لاحقًا ينقل إلى PostgreSQL.
- حظر تخمين كلمات المرور محفوظ في الذاكرة (يُصفَّر عند إعادة التشغيل).

## الإشعارات الفورية (Web Push)
- تعمل فقط عبر HTTPS (أو localhost) بعد أن يفعّلها السائق من زر «تفعيل الإشعارات الفورية» في صفحة `/driver`.
- مفاتيح VAPID تُنشأ تلقائيًا وتُحفظ في قاعدة البيانات؛ اضبط `VAPID_SUB` (مثل `mailto:you@domain.com`).
- الإشعار يظهر بنغمة النظام الافتراضية؛ النغمة الخاصة بطلبيستا تُسمع داخل التطبيق المفتوح فقط. للنغمة الخاصة في الخلفية يلزم تطبيق أصلي (FCM).
- على iPhone تلزم إضافة الصفحة إلى الشاشة الرئيسية (iOS 16.4+)، وهذا غير مُجهَّز بعد (لا manifest ولا أيقونات).

## المخالفات
- الإدارة فقط تسجّل المخالفة (غرامة `violation_fine` وحجب `violation_block_hours` من الإعدادات، الافتراضي 10 د.ل و24 ساعة).
- الإلغاء يتم بقيد عكسي جديد (`FINE_REVERSAL`) ولا يُحذف أي قيد؛ وكل ذلك في سجل العمليات.

## تطبيق Android (Capacitor)
انظر `mobile/README.md` لخطوات بناء APK عبر GitHub Actions وإعداد Firebase. على الخادم: `pip install -r requirements.txt` و`FCM_SERVICE_ACCOUNT_JSON`.

## الموقع (GPS) وتوزيع الطلبات حسب القرب
- الزبون والمتجر: زر «موقعي الحالي» + تعديل الدبوس بالضغط على الخريطة؛ الإحداثيات تُحفظ مع الطلب (`pickup_lat/lng`, `dropoff_lat/lng`). بدون إذن الموقع يحدد المستخدم النقطة يدويًا.
- السائق: يُرسل موقعه مرة كل دقيقة وهو متاح والتطبيق مفتوح (قراءة واحدة، بلا تتبع مستمر) عبر `POST /api/driver/location` لحسابه فقط.
- التوزيع: أقرب سائق متاح بموقع حديث (Haversine، توسيع تدريجي لنطاق البحث 5/15/50/500 كم)، سائق واحد في كل مرة، وعند الرفض أو انتهاء المهلة ينتقل للأقرب التالي. تعادل المسافة (نطاق 100 م) يحسمه الأحدث تحديثًا. الحد الأقصى طلبان نشطان (`max_active_orders`).
- الخريطة: بلاطات OpenStreetMap العامة (للاستخدام الخفيف فقط). للإنتاج اضبط `window.TB_TILES` على مزود خرائط بمفتاح.
- إعدادات من لوحة الإدارة: `max_active_orders`، `location_max_age`، `store_fee_normal`، `store_fee_urgent`.
- المساعدة والدعم للمتجر: اضبط `SUPPORT_PHONE` و`SUPPORT_WHATSAPP` على الخادم (مثال: `+218...` و`218...`).
- أندرويد: صلاحيات الموقع تُضاف تلقائيًا للـManifest؛ يُطلب الإذن من المستخدم عند أول استخدام.
